## 3. `shared/chem.js` — the keystone

An **ion** is a plain object:

```js
{ sym: "SO4", name: "sulfate", charge: -2, poly: true }
{ sym: "Al",  name: "aluminum", charge: 3, poly: false }
```

### `Chem.formulaFor(cation, anion)`

```js
Chem.formulaFor({sym:"Al",charge:3}, {sym:"SO4",charge:-2,poly:true})
// →
{
  formula: "Al2(SO4)3",
  html:    "Al<sub>2</sub>(SO<sub>4</sub>)<sub>3</sub>",
  ratio:   [2, 3],          // [cation count, anion count], lowest whole terms
  needsParens: true,        // true iff any polyatomic carries a subscript > 1
  parts: [
    { sym:"Al",  charge: 3, poly:false, count:2, parens:false },
    { sym:"SO4", charge:-2, poly:true,  count:3, parens:true  }
  ]
}
```

**Algorithm:** `lcm(|c+|,|c−|)` → counts → reduce by `gcd` → parenthesize a
polyatomic **iff** its count > 1.

**Invariants** (property tests, whole cross-product, not samples):
- `count_c * charge_c + count_a * charge_a === 0`, exactly, always
- `gcd(ratio[0], ratio[1]) === 1`
- parentheses appear **iff** `poly && count > 1`
- a count of 1 is never rendered — no `Na1Cl`, no `(OH)1`
- deterministic: same input → same string, every call

**Throws `TypeError`** on: non-integer charge, `cation.charge <= 0`,
`anion.charge >= 0`, missing `sym`. The message must **name the offending field**
(`charge` or `sym`). This is pinned deliberately, above a bare type check: mutation
testing showed that a weakened guard (`charge < 0` instead of `<= 0`) still throws a
TypeError — but from `gcd()` receiving a NaN much later, not from validation. The
suite passed on luck. A future refactor making `gcd()` tolerant would turn that luck
into a silently wrong formula shown to a student.

`poly` is **inferred when the flag is absent**: a sym matching `/^[A-Z][a-z]?$/` is
monatomic, anything else polyatomic. An explicit boolean always wins. This exists so
a hand-constructed ion that forgets the flag cannot silently emit `NH42SO4` — a wrong
answer taught to a student.

**Bank YAML must NOT carry `poly` by hand.** `build_banks.py` stamps it from the YAML
section, which is structural ground truth a regex cannot drift away from, and treats
a flag contradicting its section as a hard error rather than guessing. Shipped data
therefore always arrives with an explicit flag and the inference above never runs on
it — inference remains only for ions built by hand in engine code.

### Rendering helpers

| Call | Returns |
|---|---|
| `Chem.symHtml("SO4")` | `"SO<sub>4</sub>"` — digits become real `<sub>` (D5) |
| `Chem.ionHtml(ion)` | `"Na<sup>+</sup>"`, `"Al<sup>3+</sup>"`, `"SO<sub>4</sub><sup>2−</sup>"` |
| `Chem.chargeLabel(n)` | `"+"`, `"3+"`, `"−"`, `"2−"` — U+2212 MINUS, never hyphen. `chargeLabel(0)` returns `"0"`; it is unreachable through `formulaFor`, which rejects a zero charge. |
| `Chem.MINUS` | the U+2212 character, so callers never embed the literal |
| `Chem.netCharge(result)` | number; `0` for every valid result |
| `Chem.gcd(a,b)` / `Chem.lcm(a,b)` | integers, positive |

A charge of ±1 renders as a bare sign with **no** digit. Never Unicode subscripts —
real `<sub>`/`<sup>` only (D5, VoiceOver).

## 4. `shared/drag.js` + `drag.css`

Pointer Events only. **The HTML5 Drag and Drop API is forbidden** — `dragstart` does
not fire from a finger on iOS Safari.

```js
var handle = Drag.attach(rootEl, {
  itemSelector: "[data-drag]",
  zoneSelector: "[data-zone]",
  threshold: 8,                    // px of movement before a tap becomes a drag
  ghost: function (item) { ... },  // optional; default = styled clone
  onLift:   function (item) {},
  onOver:   function (item, zone /* or null */) {},
  onCommit: function (item, zone, method) {},  // method: "drag" | "tap" | "key"
  onCancel: function (item) {}
});
handle.destroy();
handle.refresh();   // re-scan items/zones after DOM changes
```

Required behaviour — `mobile-auditor` checks every line of this:

- `setPointerCapture` on **`rootEl`**, which is never re-parented. Capturing on the
  tile breaks the moment the tile is moved into a zone.
- Ghost is `position:fixed`, `pointer-events:none` — otherwise `elementFromPoint`
  returns the ghost and no zone is ever found.
- `pointercancel` **and** `pointerup` both tear down. iOS fires `pointercancel` on
  notification banners and edge swipes; unhandled leaves an orphan ghost on screen.
- The synthetic `click` after a drag is swallowed (capture-phase, one shot).
- Movement under `threshold` = a tap → selection mode → next zone tap commits with
  `method:"tap"`. This is the accessibility path, not an extra.
- Keyboard: items are `tabindex="0"`; Enter/Space selects, then Enter/Space on a
  focused zone commits with `method:"key"`. `aria-grabbed` kept in sync.
- `drag.css` owns `touch-action:none`, `-webkit-touch-callout:none`,
  `user-select:none` + `-webkit-user-select:none` on `[data-drag]`.
  **Never set `touch-action` from JS** — inside `pointerdown` is already too late.
- Honours `prefers-reduced-motion`.

### `meta.standard` — VERIFIED, do not substitute

The current framework is the **South Carolina College- and Career-Ready Science
Standards 2021**. The 2014 "Academic Standards and Performance Indicators" is
superseded — never tag with an `H.C.*` code. 2021 codes are hyphenated with a course
prefix (`C-` = Chemistry) and are NGSS-derived: `C-PS1-1` is word-for-word `HS-PS1-1`.

| Bank about | Code | Basis |
|---|---|---|
| ion charges, periodic position | `C-PS1-1` | SCDE Chemistry Performance Targets lists under C-PS1-1: students predict *"number and charges in stable ions that form atomic groups"* |
| writing ionic formulas | `C-PS1-2` | SCDE's own 2021↔2014 crosswalk maps retired `H.C.3A.2` (write/interpret formulas of binary ionic compounds) forward to `C-PS1-2` |
| periodic trends (`periodic/` app) | `C-PS1-1` | same Performance Targets entry, trends clauses iii and iv |

Caveat, verified and recorded rather than papered over: the 2021 framework has **no
performance expectation dedicated to ionic nomenclature**, and **no SC 2021 document
names polyatomic ions at any code**. `C-PS1-2` is the sanctioned current home via the
crosswalk, not an exact match. Do not claim any code "covers polyatomics."

**No hardcoded answers.** If `Chem.formulaFor()` can compute it, the bank carries the
inputs only. A matrix bank lists cations and anions; it never lists the twelve
resulting formulas. `build_banks.py` enforces this mechanically — see §6.

### `banks_src/ions.yaml` (reference bank, `engine: reference`)

```yaml
monatomic:
  - { sym: Na, name: sodium,  z: 11, group: 1,  charge: 1 }
  - { sym: O,  name: oxygen,  z: 8,  group: 16, charge: -2 }
multivalent:               # metals with more than one common charge — Cascade "wilds"
  - { sym: Fe, name: iron,   z: 26, charges: [2, 3], stock: [iron(II), iron(III)] }
polyatomic:
  - { sym: SO4,   name: sulfate,   charge: -2 }
  - { sym: NH4,   name: ammonium,  charge: 1 }
  - { sym: C2H3O2, name: acetate,  charge: -1, aliases: [CH3COO] }   # D3
```

D3: acetate accepts both notations via `aliases`; **display is always `C2H3O2`**.

### Optional keys — allowed, `build_banks.py` must NOT reject them

`z`, `group`, `stock`, `aliases`, `alt_names`, `note`, `derive_charges`.

- `aliases` — alternate **formula** notation (`CH3COO` for acetate). D3 only.
- `alt_names` — alternate **name** (`bisulfate` for hydrogen sulfate). Deliberately a
  different key from `aliases`; overloading one key with two meanings rots.
- `note` — a caveat that must survive compilation. YAML comments are discarded by the
  compiler, so anything the *site* may need to show goes here, not in a `#` comment.

### `derive_charges` — the mercury(I) hazard

Mercury(I) is not a lone `Hg⁺`. It is the diatomic dimer **`Hg2²⁺`** — two mercury
atoms bonded to each other sharing a 2+ charge. This is a live derivation hazard, not
a footnote:

```
Hg(1+)  + Cl(1−)  → HgCl     ← WRONG. The real compound is Hg2Cl2.
Hg(1+)  + O(2−)   → Hg2O     ← right, but only by coincidence.
```

A formula that is wrong only against *some* anions is the worst kind of wrong: it
passes a spot check and teaches a wrong answer anyway. Two changes:

1. `Hg2` is added to `polyatomic` as `{ sym: Hg2, name: "mercury(I)", charge: 2 }`.
   It genuinely *is* a polyatomic cation, so `formulaFor` handles it correctly with
   no special case: `Hg2²⁺ + Cl⁻ → Hg2Cl2` ✓, `Hg2²⁺ + PO4³⁻ → (Hg2)3(PO4)2` ✓.
2. A `multivalent` entry may carry `derive_charges: [2]` — the subset of `charges`
   that may be handed to `formulaFor()` as a **monatomic** ion. Absent = all charges
   are derivable. `build_banks.py` validates it is a non-empty subset of `charges`.
   Mercury keeps `charges: [1, 2]` (both are real, and Cascade teaches both) but only
   `2` is derivable as `Hg`.

Any engine that builds compounds draws cations from `derive_charges`. Cascade, which
only asks *what charge does this element form*, uses the full `charges` list.

### `derivable: false` — reference-only ions

Same hazard as mercury, different mechanism. `H3O⁺` is a real ion and belongs in a
reference bank, but deriving compounds from it produces rows like `H3O(1+) + Cl(1−) →
H3OCl`. That is arithmetically correct and chemically nonsense — "hydronium chloride"
is just HCl dissolved in water, and no chemistry teacher would accept `H3OCl` as an
answer. Formally-correct-but-not-a-compound is the same failure mode as `HgCl`: it
survives every net-charge check and still teaches a wrong answer.

An ion may carry `derivable: false`, meaning **reference and recognition only, never
fed to `formulaFor()` by a game**. Currently: `H3O` only.

- `build_banks.py` validates it as a boolean and passes it through.
- `tests/derive.js` skips these ions and records them in its `EXCLUDED FROM
  DERIVATION` block — excluded loudly, never silently dropped.
- Matrix draws its tile sets only from ions where `derivable !== false`.

Note the boundary. `Al³⁺ + O2²⁻ → Al2(O2)3` **stays**: aluminum peroxide is not a
compound you would find on a shelf, but the exercise is *"given these two ions, write
the neutral formula"*, and `Al2(O2)3` is what a teacher marks correct. `H3OCl` fails
that test too — the ion pair itself is never posed. Exclude the ion, not the formula.

## 9. Charge Cascade (`cascade/`)

Locked by D1: **center lane + 2×4 bucket grid**. Seven columns would give 55px targets
on a 390px phone. Speed should depend on knowing the answer, not on finger precision.

**Correction to D1's arithmetic** (the decision stands; the number attached to it was
wrong). D1 claims ~120px per bucket. Actual, on a 390px phone with `--pad: 18px` and
8px gaps: `390 − 36 − 24 = 330 / 4 = ~82px`. That is still **1.9× the 44px HIG
minimum** and far better than the 55px seven-column layout D1 rejects, so the decision
holds — but do not expect 120px targets. Reaching 120px would need a 2-wide grid,
costing four rows of vertical space the falling lane needs.

### The eight buckets

```
┌────────┬────────┬────────┬────────┐
│   1+   │   2+   │   3+   │  WILD  │
├────────┼────────┼────────┼────────┤
│   1−   │   2−   │   3−   │ NOBLE  │
└────────┴────────┴────────┴────────┘
```

- `WILD` — elements that commonly form **more than one** charge (the `multivalent`
  section). Answering "iron" with "2+" is not wrong so much as incomplete; the wild
  bucket is what makes that teachable instead of punishing.
- `NOBLE` — noble gases, which form no monatomic ion at all. Worth a bucket: without
  it the game silently teaches that every element has a charge.

### The bank — `banks_src/chem-ion-charges.yaml`, `engine: cascade`

**The bucket for a tile is DERIVED, never stored.** The bank lists which elements are
in play; the answer comes from `banks/ions.json` at runtime:

| Where the sym is found in `ions.json` | Bucket |
|---|---|
| `monatomic`, `charge > 0` | `1+` / `2+` / `3+` by magnitude |
| `monatomic`, `charge < 0` | `1−` / `2−` / `3−` by magnitude |
| `multivalent` (more than one charge) | `WILD` |
| listed in the bank's `no_ion` pool | `NOBLE` |

`no_ion` is the one membership list the bank carries, because *absence* from
`ions.json` is not evidence of anything — a typo'd sym would otherwise land in NOBLE
and be marked correct. `build_banks.py` cross-checks that no `no_ion` sym appears
anywhere in `ions.yaml`, and `chem-verifier` confirms the list is exactly the noble
gases. This is an input set, not a stored answer.

```yaml
meta: { id: chem-ion-charges, ..., engine: cascade, standard: C-PS1-1, difficulty: 3 }
config:
  buckets: ["1+","2+","3+","wild","1-","2-","3-","noble"]
  lives: 3
  levels:                  # the ramp; each level names its element pool
    - { n: 1, pool: main_group, fallMs: 4200, spawnMs: 2600 }
    - { n: 2, pool: main_group, fallMs: 3600, spawnMs: 2200 }
    - { n: 3, pool: with_wilds, fallMs: 3000, spawnMs: 1900 }
pools:
  main_group: [H, Li, Na, K, Mg, Ca, ...]     # syms only — charges come from ions.json
  with_wilds: [..., Fe, Cu, Pb, Sn]
no_ion: [He, Ne, Ar, Kr, Xe, Rn]
```

### Engine notes

- Tiles fall in the center lane on a `requestAnimationFrame` loop driven by elapsed
  time, never by frame count — a dropped frame must not slow the game down.
- A tile is committed by drag, tap, or keyboard via `Drag.attach` — all three paths
  equal, per §4. The bucket grid is the drop-zone set.
- Miss (wrong bucket or tile reaches the bottom) costs a life. Combo climbs on
  consecutive correct answers; the multiplier caps, matching `periodic/`'s feel.
- Wrong answers must state the right one. A miss that teaches nothing is a wasted
  question — show the element, its charge, and why.
- XP banks through `Store.app("cascade").finishRun(xp)` and nowhere else.

### XP weighting — decided by the user

```js
xp = Math.floor(score / xpDivisor * (meta.difficulty / 3))
```

Difficulty **3 is the neutral baseline**, so a difficulty-3 bank pays exactly what
`periodic/` pays today and nothing already earned is devalued. Difficulty 5 → ×1.67,
difficulty 2 → ×0.67. Harder work counts for more, but a 7th grader can still
out-level a 10th grader by doing more of it — which matters, because both kids share
one global level.

### The WILD bucket — decided by the user

Dropping a multivalent metal into a charge it **genuinely forms** (iron into `2+`,
checked against that ion's `charges` list) is a **near miss**:

- **no life lost** — 2+ is a real iron charge, so this is incomplete, not wrong
- **combo resets to 1×** — it costs real points, so there is pressure to learn WILD
  rather than settle for a charge that is merely plausible
- teach on the spot: *"iron also forms 3+, which is why it's WILD"*

Dropping iron into a charge it never forms is a plain miss and costs a life.

### Level ramp and the falling lane

- Advance a level every **8 correct** answers; clamp at the last level and stay there.
- Overlapping tiles are intended pressure: `spawnMs` below `fallMs` puts ~2 tiles in
  the lane at once.
- **The freeze on lift is global** — `onLift` freezes the whole rAF loop, not just the
  held tile, and `onCancel` resumes it. No tile can ever reach the bottom while
  another is in hand. This also makes the tap and keyboard paths fair: a player who
  cannot drag is not racing a timer the drag player escapes.
- Bucket ids in the bank stay **ASCII** (`"1-"`, `"2-"`). They are opaque keys and are
  never printed. Every visible label comes from `Chem.chargeLabel()`, so the student
  sees `1−` with U+2212. Do not "fix" the YAML to contain U+2212.
- `prefers-reduced-motion`: the fall becomes stepped rather than smooth; the game
  must still be fully playable.

## 10. Matrix pool constraints — from the Gate 0 audit

`chem-verifier` certified the algorithm and then asked a different question: which
rows would a *teacher* mark wrong? These are not defects in `chem.js` or in
`derived.txt` (which stays exhaustive — it is a test artifact). They are constraints on
which ions the **Matrix tier banks may draw from**, recorded before those banks exist.

**`H` is excluded from the Matrix cation pool.** Two independent reasons:

1. Against hydrogen-bearing anions it emits illiterate strings — `H(1+) + HSO4(1−)` →
   `HHSO4`, where a teacher expects `H2SO4`. Charge-balanced, correct per spec,
   and wrong on the page.
2. Even the well-formed rows are a trap. `HCl`, `HNO3`, `H2SO4` are **acids**, named by
   acid rules — "hydrochloric acid", not "hydrogen chloride" the ionic way. A naming
   cell built on `H⁺` teaches the wrong naming system.

`H` stays in Cascade, where the question is only *what charge does hydrogen form*.

**`H3O` is excluded everywhere** via `derivable: false` (§5) — already closed.

### Formula-string collisions — REQUIRED at Gate 2

Three formula strings are each produced by **two different ion pairs**:

```
MnO2  ⇐  Mn⁴⁺ + O²⁻   AND   Mn²⁺ + O2²⁻
PbO2  ⇐  Pb⁴⁺ + O²⁻   AND   Pb²⁺ + O2²⁻
SnO2  ⇐  Sn⁴⁺ + O²⁻   AND   Sn²⁺ + O2²⁻
```

metal(4+) + oxide and metal(2+) + peroxide produce an identical string. Both
derivations are correct; `chem.js` is not at fault and neither row is wrong.

**Why it breaks Matrix:** a validator comparing formula *strings* cannot tell them
apart. Ask her to build the compound from `Mn⁴⁺` and `O²⁻`, and assembling the *wrong*
tiles — `Mn²⁺` plus a peroxide tile — produces a string that validates as correct. Run
it the other way, show `MnO2` and ask her to name it, and there are two defensible
answers. In all three cases the 4+ oxide reading is the real compound and the peroxide
reading is spurious.

`PbO2` is the worst of the three: *"lead peroxide"* is a registered PubChem synonym for
lead(IV) oxide — an archaic trivial name that survived. A student who searches it lands
on `PbO2` and concludes `Pb²⁺ + O2²⁻` was right, when the compound contains no peroxide
ion at all. **The wrong answer is externally corroborated**, which is the hardest kind
to talk a student out of.

**Fix, required before Matrix ships:** either keep peroxide out of any tier that also
offers a 4+ metal, or have the validator compare the **ion pair**, never the output
string.

Note what these three have in common with mercury: no mechanical check can catch them.
The compiler can guarantee `derivable: false` *means* what it says; it cannot know
which ions *should* carry it. That judgment is chemistry, and it belongs to
`chem-verifier` — which is exactly why the auditor is a separate agent that writes no
code and has no stake in the data passing.
